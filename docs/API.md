# HTTP API reference

Every route exposed by `onitsir-server` (`packages/onitsir-server/app/`).
Base URL in local development: `http://localhost:8000`.

Interactive docs are generated by FastAPI at `/docs` (Swagger) and `/redoc`.
This file is the hand-maintained contract; the generated docs are authoritative
for exact schema details.

## Conventions

- All request and response bodies are JSON.
- Mission IDs are UUID4 strings issued by `POST /api/mission`.
- Missions are held in an **in-memory dict** (`_MISSIONS` in
  `app/routes/mission.py`). They do not survive a process restart, and they are
  not shared across replicas. See [Known limitations](#known-limitations).
- There is currently **no authentication on any route**. Do not expose this
  service to an untrusted network. See [Known limitations](#known-limitations).

## Health

### `GET /health`

```json
{ "status": "ok", "roster_size": 164 }
```

`roster_size` is `0` if the startup hook has not yet populated
`app.state.roster`.

## Roster: divisions and agents

### `GET /api/divisions`

Returns one object per roster category, sorted by category id. `agentCount` is
computed live from `roster.category_counts()` and is never hardcoded â this is
the fix for historical specialist-count drift.

```json
[
  { "id": "design", "name": "Design Division", "emoji": "...", "color": "pink",
    "description": "Making it beautiful, usable, and delightful.", "agentCount": 8 }
]
```

### `GET /api/agents`

Returns every specialist in the roster (164 records across 14 categories).

```json
[
  { "id": "design-brand-guardian", "name": "Brand Guardian", "category": "design",
    "description": "...", "color": "indigo", "emoji": "...", "vibe": "",
    "filePath": "" }
]
```

`filePath` is the specialist's `persona_path` when one exists and `""`
otherwise. Most roster records currently have no persona file; see
[Known limitations](#known-limitations).

### `GET /api/agents/{category}/{agent_id}`

As above for a single specialist, plus a `content` field holding the resolved
markdown persona body when a persona file exists.

- `404` if the id is unknown, **or** if the id exists but its category does not
  match the `{category}` path segment.

## Router

### `GET /api/router/prefilter?goal={goal}&limit={limit}`

Deterministic keyword shortlist, intended as a cheap pre-filter in front of an
LLM planner. `limit` defaults to `8`.

```json
[ { "id": "engineering-backend-architect", "name": "Backend Architect",
    "category": "engineering", "description": "...", "score": 12,
    "confidence": "high" } ]
```

`confidence` is derived from `score`: `high` at `>= 8`, `medium` at `>= 4`,
otherwise `low`.

- `400` if `goal` is empty.

### `POST /api/router/route`

```json
{ "goal": "launch a mobile game", "crew_size": 3 }
```

Returns a staffed crew in the same assignment shape as `prefilter`.

- `400` if `goal` is empty.

## Missions

### `POST /api/mission`

```json
{ "goal": "ship a landing page", "crew_size": 3,
  "budget_usd": 1.0, "hitl_mode": "never" }
```

`hitl_mode` is one of `never`, `on_deny`, `on_threshold`, `always`.

```json
{ "mission_id": "d29e...", "crew": [ /* assignments */ ] }
```

### `GET /api/mission/{mission_id}`

```json
{ "mission_id": "d29e...", "goal": "ship a landing page",
  "crew": [], "phase_log": [], "shipped": false, "blocked_reason": null,
  "hitl_required": false, "hitl_pending_phase": null, "audit_intact": true }
```

`audit_intact` is recomputed on every call by verifying the mission's ledger
hash chain.

- `404` if the mission id is unknown.

## Governance gate

### `POST /api/mission/{mission_id}/gate`

The single server-side source of ALLOW/DENY/HITL truth. The TypeScript client
calls this before each chain step and never re-implements the decision.

```json
{ "tool_name": "github.write", "cost_usd": 0.02,
  "nonce": "step-7", "params": {}, "tags": ["no_harm"] }
```

```json
{ "verdict": "DENY", "reason": "budget_exhausted",
  "deny_reason": "budget_exhausted" }
```

- `verdict` is `ALLOW`, `DENY`, or `HITL`.
- `reason` is the raw stable reason string from the Governor.
- `deny_reason` is that reason classified into the closed `DenyReason` value
  set, which is what the UI colors on.
- A `HITL` verdict also opens a pending HITL prompt on the mission and emits a
  `HITL_PROMPT` event.
- **Cost is deducted and the repeat counter incremented before the decision is
  made**, so a denied call still consumes budget. This is deliberate: it makes
  hostile retries expensive rather than free.
- A `DENY` trips the mission's circuit breaker. Every subsequent gate call on
  that mission returns `DENY circuit_open` until the circuit is cleared.

Full precedence order and reason semantics: [`SHACKLE.md`](SHACKLE.md).

## Custody: authorize and execute

`/gate` returns a verdict a caller may ignore. These two routes are the
enforced path: a tool in `onitsir.custody.PROTECTED_TOOLS` cannot execute
without a single-use, argument-bound capability, and the only thing that mints
one is a decision that returned `ALLOW`.

Normative rules: [`SHACKLE.md` section 8](SHACKLE.md).

### `POST /api/mission/{mission_id}/authorize`

Same request shape as `/gate`, plus an optional `ttl_s`.

```json
{ "tool_name": "email.send", "cost_usd": 0.02, "nonce": "step-7",
  "params": { "to": "ops@example.com" }, "tags": [], "ttl_s": 60 }
```

```json
{ "verdict": "ALLOW", "reason": "within_thresholds",
  "deny_reason": "unspecified", "protected": true,
  "capability": {
    "token_id": "3rJ...", "mission_id": "d29e...",
    "tool_name": "email.send", "nonce": "step-7",
    "args_digest": "9f2c...", "expires_at": 1785479938.0,
    "signature": "a41b..." } }
```

- `capability` is present **only** for an `ALLOW` on a protected tool. A
  `DENY`, a `HITL`, or an unprotected tool all return `null`.
- `protected` says whether `/execute` will demand a capability for this tool.
- The capability is bound to `mission_id`, `tool_name`, `nonce` and the
  canonical hash of `params`. Changing any of them at execution time is a
  `403`.
- Cost accounting and circuit-breaker behaviour are identical to `/gate`,
  because `/authorize` calls the same `Governor.evaluate()`.

### `POST /api/mission/{mission_id}/execute`

```json
{ "tool_name": "email.send", "capability_token": "3rJ...",
  "nonce": "step-7", "params": { "to": "ops@example.com" } }
```

```json
{ "ok": true, "tool_name": "email.send", "result": { } }
```

A refusal is `403` with a structured `detail`:

```json
{ "detail": { "ok": false, "tool_name": "email.send",
              "reason": "args_mismatch",
              "detail": "presented arguments do not match the arguments authorized" } }
```

`reason` is one of `missing`, `replayed`, `expired`, `mission_mismatch`,
`tool_mismatch`, `nonce_mismatch`, `args_mismatch`, `bad_signature`.

- The token is consumed on first presentation, correct or not. A misaimed
  token is burned rather than left available for a second attempt.
- A tool with no registered implementation is `404`, checked **after**
  redemption, so a refused call cannot have run.

### `GET /api/mission/{mission_id}/custody`

```json
{ "mission_id": "d29e...",
  "entries": [ { "index": 0, "event": "capability_minted", "tool_name": "email.send",
                 "token_id": "3rJ...", "detail": "9f2c...", "prev_hash": "000...",
                 "entry_hash": "7ab..." } ],
  "intact": true, "live_capabilities": 0 }
```

`event` is `capability_minted`, `capability_spent` or `capability_refused`.
This chain is separate from `/api/audit/{id}`: that one records what was
decided, this one records whether anything executed without a decision.

## Human-in-the-loop

### `GET /api/mission/{mission_id}/hitl`

```json
{ "mission_id": "d29e...", "hitl_required": true,
  "pending_phase": "github.write", "pending": { /* pending prompt */ },
  "timeout_s": 60.0 }
```

### `POST /api/mission/{mission_id}/hitl`

```json
{ "decision": "approve" }
```

`decision` is `approve`, `reject`, or `modify`. Resolving clears the pending
prompt and emits a `HITL_RESPONSE` event.

An unanswered prompt is resolved by `Governor.hitl_timeout()` to
`DENY hitl_timeout`. Silence is never treated as approval.

## Verification and evidence

### `POST /api/mission/{mission_id}/verify-step`

Iron Law check for one chain step, via `ChainStepEvidenceProducer`.

```json
{ "agent_id": "engineering-backend-architect",
  "task": "add rate limiting to the gate route",
  "output": "...", "command": "pytest -q" }
```

```json
{ "passed": true, "command": "pytest -q", "output_summary": "..." }
```

The producer rejects output shorter than 20 characters, output containing
refusal markers, and output with no keyword overlap with the stated task.

### `POST /api/mission/{mission_id}/evidence`

Wraps a tool integration's side effect as evidence.

```json
{ "tool_name": "github.write", "command": "git push",
  "output": "...", "passed": true }
```

```json
{ "ok": true, "passed": true }
```

## Events

### `GET /api/mission/{mission_id}/events?since={n}`

Polling fallback for environments without WebSocket support.

```json
{ "events": [ { "type": "GOVERNOR_VERDICT", "tool_name": "github.write",
                "verdict": "ALLOW", "reason": "within_thresholds" } ],
  "next_since": 4 }
```

Pass the previous `next_since` back as `since` to page forward.

Event types: `MISSION_CREATED`, `GOVERNOR_VERDICT`, `HITL_PROMPT`,
`HITL_RESPONSE`, `STEP_VERIFIED`, `TOOL_EVIDENCE`.

## Audit ledger

### `GET /api/audit/{mission_id}`

```json
{ "mission_id": "d29e...",
  "entries": [ { "index": 0, "at": 1767000000.0, "tool_name": "github.write",
                 "verdict": "ALLOW", "reason": "within_thresholds",
                 "prev_hash": "000...0", "entry_hash": "9f2...", "signed": false } ],
  "head": "9f2..." }
```

`prev_hash` of entry 0 is the genesis constant (64 zeros). `signed` is true
only when the Governor was constructed with a signing key.

### `GET /api/audit/{mission_id}/verify`

```json
{ "mission_id": "d29e...", "intact": true, "length": 12 }
```

`intact` is false if any entry was modified, removed, or reordered. The ledger
is tamper-**evident**, not tamper-proof.

## Swarm

### `GET /api/swarm/status`

```json
{ "total_agents": 3,
  "by_status": { "online": 2, "stale": 1, "down": 0 },
  "active_assignments": 2 }
```

Liveness is recomputed on read: an agent goes `stale` after 5 s without a
heartbeat and `down` after 15 s.

### `POST /api/swarm/register?agent_id={id}&capabilities={csv}`

`capabilities` is a comma-separated string, not a JSON array.

```json
{ "agent_id": "worker-1", "status": "online" }
```

### `POST /api/swarm/heartbeat?agent_id={id}`

```json
{ "ok": true }
```

`ok` is false when the agent id is not registered.

Both swarm write routes take **query parameters rather than a JSON body**, which
is inconsistent with the rest of the API. See
[Known limitations](#known-limitations).

## WebSocket

### `WS /ws/mission/{mission_id}`

Streams the same event objects as `GET /api/mission/{id}/events`, pushed as
they are appended. The server polls the mission's event list every 250 ms and
sends any new entries.

If the mission id does not exist, the socket stays open and emits
`{"type": "ERROR", "detail": "mission not found"}` once per second rather than
closing.

**This socket has no authentication.** See
[Known limitations](#known-limitations).

## Error shapes

FastAPI's defaults are used throughout.

| Status | Meaning | Body |
|---|---|---|
| `400` | invalid input, e.g. empty `goal` | `{"detail": "..."}` |
| `404` | unknown mission id or agent id | `{"detail": "Mission not found."}` |
| `422` | request body failed Pydantic validation | `{"detail": [ ... ]}` |

## Known limitations

Stated here rather than discovered in production:

1. **No authentication or authorization on any route, including the
   WebSocket.** Anyone who can reach the port can submit missions, resolve HITL
   prompts, and read audit ledgers. Bind to localhost or put an authenticating
   reverse proxy in front of it.
2. **No rate limiting.** A single client can exhaust CPU via
   `/api/router/prefilter` on a large roster.
3. **CORS is currently `allow_origins=["*"]`.** Acceptable for local
   development; wrong for any deployment.
4. **Mission state is in-memory and single-process.** Restarting loses every
   mission and its audit ledger. Running more than one replica behind a load
   balancer will produce 404s for missions created on a different replica.
5. **Swarm write routes use query parameters instead of validated request
   bodies**, so they get no Pydantic validation.
6. **Most roster records have no persona file.** The repository ships 164 roster
   *records* and a single persona markdown body. `content` and `filePath` are
   therefore empty for nearly every specialist.
7. **The `startup` hook uses the deprecated `@app.on_event` decorator**, which
   FastAPI will eventually remove in favor of the lifespan context manager.
8. **Custody is per-process and covers a fixed tool set.** The capability
   holder and the custody ledger live in the same process as the mission
   registry, so the enforcement guarantee does not survive a restart and is
   not shared across replicas. A tool outside
   `onitsir.custody.PROTECTED_TOOLS` executes without a capability by design.
9. **The default protected-tool implementations are inert.** They echo their
   arguments and perform no side effect. A deployment registers real ones.

Items 1-5 and 7-8 are tracked in [`ROADMAP.md`](ROADMAP.md).
